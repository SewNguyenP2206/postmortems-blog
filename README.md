## ✨ Features

- 🌑 **Dark DevOps UI** – GitHub-inspired design with severity color coding
- 📋 **Auto-indexed** – GitHub Actions scans `postmortems/` and builds `manifest.json` automatically on every push
- 🔍 **Search & Filter** – Filter by severity (P0–P3), status, services, or free-text search
- 📊 **Stats Dashboard** – Total incidents, P0 count, MTTR, 30-day incident timeline
- 📖 **Full Markdown** – Each postmortem renders rich Markdown with syntax highlighting, tables, TOC
- 📱 **Responsive** – Works on mobile, tablet, desktop

## 🚀 Getting Started

### 1. Enable GitHub Pages

1. Go to **Settings → Pages**
2. Set **Source** to `GitHub Actions`

### 2. Add a Postmortem

Create a new `.md` file in `postmortems/`:

```bash
cp postmortems/_TEMPLATE.md postmortems/2024-12-01-my-incident.md
# Edit the file, then:
git add postmortems/2024-12-01-my-incident.md
git commit -m "postmortem: my incident title"
git push
```

That's it! GitHub Actions will:
1. Scan `postmortems/` and update `manifest.json`
2. Deploy the updated site to GitHub Pages

### 3. Naming Convention

```
postmortems/YYYY-MM-DD-short-slug.md
```

Example: `postmortems/2024-10-01-database-outage.md`

## 📄 Postmortem Frontmatter

Each `.md` file **must** start with a YAML frontmatter block:

```yaml
---
title: "Service Name – Incident Description"
date: "2024-10-01"
severity: "P0"          # P0 | P1 | P2 | P3
status: "resolved"      # resolved | ongoing | monitoring
duration: "2h 34m"
services:
  - "PostgreSQL"
  - "API Gateway"
author: "Platform Team"
tags:
  - "database"
  - "production"
summary: "One-sentence summary of the incident."
---
```

| Field | Required | Values |
|---|---|---|
| `title` | ✅ | Incident title |
| `date` | ✅ | `YYYY-MM-DD` |
| `severity` | ✅ | `P0`, `P1`, `P2`, `P3` |
| `status` | ✅ | `resolved`, `ongoing`, `monitoring` |
| `duration` | — | e.g. `2h 34m`, `45m` |
| `services` | — | Array of affected services |
| `author` | — | Team or person name |
| `tags` | — | Array of tags for filtering |
| `summary` | — | One-sentence description |

## ⚙️ GitHub Actions Workflow

The workflow triggers on every push to `main` that touches `postmortems/*.md` or the site files.

It:
1. Scans `postmortems/` for all `*.md` files
2. Generates `postmortems/manifest.json` (sorted newest-first)
3. Commits `manifest.json` back to `main`
4. Deploys the entire site to GitHub Pages
